# P21 procedural 3D source family

Status: **nineteen editable procedural mesh factories and 38 high/low GLBs generated and machine-validated; browser stills rendered; owner visual review remains pending.** The set contains Neon X/O glyphs, Coin, Crown, all eleven canonical rank badges, Trophy, a provisional decorative reward chest, and separate Neon X/O board plates. These studies are not wired into the website, gameplay, product economy or native runtime. The approved website rasters remain unchanged.

`factories.mjs` exports `createAsset(THREE, name, quality)` and `assetNames`. Quality is `high` or `low`. Every factory returns an editable named hierarchy with a center `Pivot`, unit root scale, front +Z and vertical +Y. The models use genuine extruded, lathed, torus, tube, box and faceted solid geometry with generated unit normals and UVs. GLBs use procedural `MeshStandardMaterial` metallic-roughness parameters and have no image or external-buffer dependencies.

The rank source inventory is in `assets/p21/art/ranks/PROMPTS.json`: ten 1254×1254 RGBA tier PNGs plus the retained Diamond reference in `assets/p21/art/crystal-source.png` and approved `assets/p21/art/ranks/diamond.webp`. The source art was inspected before modeling. The geometry preserves the shield/segmented-wing family and varies its approved tier palette, relief, crystal and finial design. It is a 3D reconstruction study, not an exact raster trace. Wood grain, stone microtexture, and crystal normal/roughness/metalness maps are not fabricated; material-map work remains open.

The Trophy source is `assets/p21/art/trophy-source.png`. The local P21 asset registry records no owner-supplied chest image. `reward-chest` is therefore a clearly provisional closed black-and-gold decorative model with no contents, economy behavior or store/catalog meaning. It needs an owner source/art-direction review before use. The separate `board-x` and `board-o` meshes follow the existing Card 3 reference in `docs/p21-web/evidence/41e74bf/home-desktop.png`, `apps/web/site.js:siteMiniTheme`, and `apps/web/styles.css:.mx-art-board`; each carries diagonal marks at cells 0, 4 and 8. They are standalone geometry studies and do not replace the live interactive board or homepage art.

`scripts/p21/export-three.mjs` regenerates `exports/` and `provenance.json`. It checks geometry, normals, UVs, bounds, centered pivots, unit scale, GLB v2 headers and embedded buffers, then loads each output through Three.js `GLTFLoader` and compares readback counts and bounds. `scripts/p21/three-qa.cjs` verifies the full 19×2 model set in an isolated, unauthenticated headless Chromium context with a strict loopback path allowlist. It renders transparent front and quarter PNGs in `stills/` and records GLTF readback, alpha coverage, renderer errors, source hashes and server request audit in `render-evidence.json`. Current browser evidence is software WebGL test-rendering; it does not demonstrate hardware GPU, real-browser/device performance, or owner art acceptance.

Three.js 0.180.0 is a local ignored build tool under `.artifacts/p21-three-tools/`, not a production dependency. Its exact package version/license and source hashes are recorded in `provenance.json`. The reconstruction workflow consulted img2threejs v2.0.0/Apache-2.0 guidance; no code was copied or host skill installed.

Do not activate these models until those reviews are complete.
