# V3.3 - private rooms and ten-player tournaments

## Scope and continuity

This feature branches from V3.2.1 at `6e80a6c629148a26e28637185f626f67c744afda`. It adds rooms/tournaments without replacing the existing app, theme stylesheet, icons, game engine, economy formulas or authority. The home screen gains a fifth mode, Tournaments; the existing five bottom-navigation destinations remain unchanged.

Private Match now opens a room hub with One device, Same Wi-Fi and Online choices. Every private room is free: no Coins, Crowns, global Elo or monetary rewards. Public Tournaments are a separate, server-authoritative product. No fictional opponents or automatic bot replacements are added.

## What is implemented versus deployed

| Capability | V3.3 delivery |
|---|---|
| One-device private tournament | Playable locally with 2-10 entered player names; fixtures run sequentially |
| Separate phones on the same Wi-Fi | Working Node LAN host, guest sessions, room codes, ready checks, real moves and reconnect |
| Private online rooms | Working authenticated HTTP integration; deploy with the existing identity service |
| Public equal-entry tournaments | Working table matching, consent, escrow and settlement against the existing SQLite wallet state; paid eligibility disabled by default |
| Phone hosting without another runtime/device | Not implemented in this browser build; native transport integration is required |
| Bluetooth/NFC buttons | Not fabricated; no unsupported radio controls are displayed |
| Production rollout/store approval | Not supplied by this branch |

The tested LAN setup runs the host service on a laptop or another Node-capable device. Android and iOS participants use their browsers. A browser tab cannot expose this Node HTTP server. An Android terminal runtime may be technically possible but is not the supported consumer flow and was not tested.

### Run an internet-free party

1. Install Node 22.13+ on the hosting computer and obtain the complete repository before going offline.
2. Connect all players to the same trusted router or hotspot. It must allow client-to-client traffic and enough connected devices; guest/client isolation can block the host.
3. Run `npm run start:lan`. The console prints local URLs such as `http://192.168.1.20:8081`.
4. Open that URL on each phone. The host uses Private Match > Same Wi-Fi > Create. Guests enter their own names and the room code, or open the copied invite URL.
5. Everyone readies; the host starts. Keep the server awake. A room supports ten players including the host, not ten guests plus a host.

The LAN server serves the app files locally and removes external font/CDN requests. Inline SVG fallback icons and system font fallbacks keep it usable on a first visit without internet. Exact downloaded Figma font appearance is not guaranteed offline. A saved guest token permits reconnect on the same browser; clearing browser storage loses that guest identity.

LAN guest sessions never access account currency. This HTTP service is for a trusted local network, not port forwarding or public deployment. Transport encryption and production identity are required for Internet use.

### Native direction

For a later phone-hosted iOS/Android application, use a native Nearby Connections star (one host, multiple peers), with host-authoritative commands and snapshots. Google documents Android/iOS support and offline Bluetooth/BLE/Wi-Fi operation. Capacity and OS background behavior still require a real ten-device test. NFC can transfer an invite, not replace a persistent match connection. Browser Bluetooth is not a dependable universal Android/iOS lobby transport; WebRTC data channels would require signaling and a different transport adapter.

## Lobby rules

- Capacity: 10; a private duel is limited to 2. League/Knockout need at least 2; Mixed needs at least 4. Public tables require exactly 10.
- The host selects format and thinking clock before start. Configuration changes invalidate all ready confirmations.
- Each member readies against the displayed rules version. No late joins or roster edits after start.
- Private hosts can transfer hosting or remove a member in the lobby. If a host leaves the lobby, ownership passes to the first remaining member.
- Starting requires everyone ready. Private tournaments never reserve money.
- Public tables are oldest eligible waiting tables, with a maximum 200-Elo participant spread and blocked-account checks. Users cannot select a profitable public opponent list or occupy two public queues.
- Public lobbies expire after 5 minutes; private lobbies after 30 minutes. No entry is charged for joining, declining, leaving or an expired lobby.
- Private hosts may pause/resume. Public hosts/players cannot pause competition clocks or declare outcomes.

## Formats

### League: full round robin

Every player plays every other once. At ten players this is 45 fixtures over nine rounds, with up to five matches in parallel. Odd rosters use byes; no points are awarded for a bye. At ten players each starts four or five games; in a five-person group each starts twice.

Win = 2 points, draw = 1, loss = 0. Order is points, head-to-head points within the tied-points group, opponent-strength score (Sonneborn-Berger), Mini Board differential, then fewer forfeits. Remaining ties create actual placement playoffs among tied players. Registration order, wallet size and random coin flips do not decide a paid placing.

### Knockout: elimination plus placement games

For ten players, two play-ins reduce the championship bracket to eight; six players receive byes. The full classification bracket determines every position, including a genuine fifth-place result. There are 15 fixtures before drawn-game replays. Losing removes the player from title contention, not from scheduled classification games.

Private seeding is randomized. For non-power-of-two rosters, the higher seed positions receive the necessary byes. This is a friendly format, not the default public-money format.

### Mixed: group league plus knockouts

This is the public-table default. Ten players form two groups of five. Each group plays a round robin: twenty group fixtures total. Public seed order is shuffled for equal ratings and then sorted by Elo, assigned in a snake pattern: A gets seeds 1/4/5/8/9, B gets 2/3/6/7/10.

A1 plays B2; B1 plays A2. Winners contest the final; losers contest third. A3/B3 decide fifth/sixth; A4/B4 seventh/eighth; A5/B5 ninth/tenth. Total: 27 fixtures before tie-breaks/replays. Every player receives at least five games, and the top four six, assuming everyone attends.

Smaller private Mixed rooms use the same principle with balanced groups and placement games for remaining participants. A single unpaired group position takes its remaining placement. Public pots never start with fewer than ten.

## Timers and definitive results

- Private default: 3 minutes of total thinking time per player, plus 2 seconds after each legal move. Options are 2/3/5 minutes plus 2 seconds, or Off.
- Public: 2 minutes/player plus 1 second per legal move. This is a thinking bank, not 2 minutes for every turn.
- The server measures clocks. Illegal moves do not add time. Zero time loses the fixture. No skipped turns are used.
- New fixtures open after 15 seconds publicly or 5 seconds privately. After one player readies, the other has 45 seconds; failing to arrive loses that fixture. If neither readies within 2 minutes, a private tournament pauses and a public event is voided/refunded.
- League/group draws stand. Decisive draws replay with starting symbols swapped and fresh banks. After three drawn decisive attempts, the private event pauses for the host to continue; public competition voids and refunds rather than deciding money by a lottery.
- Public maximum event duration is 2 hours. Timed private events have 6 hours; untimed private events 24 hours. Expiry voids the event. One-device fixtures run sequentially to avoid timing out other tables while sharing one screen.
- Resignation and one-sided no-show lose the fixture, not refund the whole entry. Players must remain available for later classification fixtures. Leaving the UI does not pause a network match.
- Typical planning estimate: Mixed can take roughly 25-50 minutes and League longer, depending on clocks, attendance and replays. These are estimates, not guarantees or measured retention data.

The core 81-cell send rule is unchanged. All moves are validated by the existing `src/game.js`; player JSON cannot supply a winner, board replacement or clock.

## Public tables and exact payouts

All ten players contribute equally, once per event. No extra fee per fixture, rebuy or bonus is charged/minted. Currency conversions remain the existing 10 Coins = 1 Crown.

| Table | Entry each | Pool | 1st | 2nd | 3rd | 4th | 5th | 6th-10th each | Burn |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Low (Coins) | 100 | 1,000 | 360 | 200 | 130 | 110 | 100 | 0 | 100 |
| Medium (Coins) | 500 | 5,000 | 1,800 | 1,000 | 650 | 550 | 500 | 0 | 500 |
| High (Coins) | 2,000 | 20,000 | 7,200 | 4,000 | 2,600 | 2,200 | 2,000 | 0 | 2,000 |
| Premium (Crowns) | 500 | 5,000 | 1,800 | 1,000 | 650 | 550 | 500 | 0 | 500 |

Shares of the ORIGINAL pool: 36%, 20%, 13%, 11%, 10%, then zero. First gets the largest share, not more than half. Fifth receives exactly its entry. Top four profit; bottom five lose their entry. Premium's 500 Crowns = 5,000 Coins entry is above High's 2,000 Coins.

Ten percent is burned; ninety percent is paid. Retaining a fifty-percent burn would be mathematically incompatible with four strictly profitable finishers plus one break-even finisher: those five alone require more than five entries. Existing two-player 50/50 rules are NOT changed.

An equal-skill player's expected gross return is 90% of the entry, not guaranteed profit. Burning virtual currency is not cash revenue. The table values are launch hypotheses; monitor retention, acceptance, forfeits, supply and concentration before enabling live paid play.

Tournament placing does not change normal ranked Elo in V3.3, and tournament matches do not mint regular ranked win/quest/weekly bonuses. This avoids a second inflation/boosting path and keeps the earlier ranked economy unchanged. A future tournament-skill rating needs its own explicit specification.

## Money, authority and recovery

Public rule/price quotes are captured before consent. Only when all ten accept are all ten balances checked and reserved in a single SQLite `BEGIN IMMEDIATE` transaction. An insufficient or ineligible account rolls back the entire start. Existing reserved balance fields count toward wealth exactly once. `activeMatch` prevents ordinary ranked play while funds/participation belong to a running tournament.

Final rankings are generated by actual fixtures. Settlement atomically clears escrow, pays exact placements and increments the currency burn counter. Command keys and settled receipts prevent repeat payouts. Public member cancellation cannot refund a losing position. Only the trusted operator can void a running paid event; the LAN server has no paid activation option.

Restart recovery is explicit: running public events void/refund once. Private events pause with roster and board intact; their clock restores the last durable bank rather than promising exact elapsed time through a crash. Lobbies and guest sessions persist. Live reconnect uses snapshots and move revisions, not a client-provided board.

Held/suspended accounts at settlement cause a REVIEW state, not unreviewed transfers. Accounts, Coins, Crowns, journal and normal matches are stored in the SAME SQLite state as the existing economy service. There is no client-wallet import.

## Online integration

Serve the existing static app and mount `createPartyHandler` at `/api/party` before the existing economy handler. Reuse the real authenticated session resolver; never use the LAN guest resolver for public account money. `RoomStore` must use the same database path as `DurableStore`.

```js
const { RoomStore } = require('./server/rooms.js');
const { createPartyHandler } = require('./server/party-http.js');
const parties = new RoomStore(databasePath, {
  paidEntryEnabled: false,
  eligibility: () => false
});
parties.recover(); // once at service boot, NOT once per database connection
const handleParties = createPartyHandler({ store: parties, authenticate, origin });
const server = http.createServer(async (req, res) => {
  if (await handleParties(req, res)) return;
  return existingEconomyHandler(req, res);
});
const timer = setInterval(() => parties.tick(), 500);
```

`authenticate(req)` resolves `{id, name}` server-side. Player JSON cannot choose operator scope. Configure TLS, origin/host allowlists, session security, rate limits, backups, spending protections and per-platform/territory/age approval before paidEntryEnabled is set. The eligibility callback must return literal true; a Promise/truthy string cannot accidentally enable stakes.

## Risks and release gates

Ten real radio devices, hotspot interoperability, native iOS/Android wrappers and native phone-hosted Nearby transport have NOT been tested or shipped. No claim of production throughput or store approval is made.

No-show/draw event-void safeguards are financially conservative but create a possible griefing/collusive-void incentive. Repeated no-shows, repeated tied deciders and linked accounts need review/cooldowns before public launch. High-forfeit events receive a review flag; that is not a completed fraud classifier. Legal-move validation does not detect external solvers, account sharing or collusion.

Purchasable Crowns and convertible Coins retain the existing paid-entry policy gate. Non-cash-out currency and a skill game do not by themselves establish platform/legal compliance. Public stakes must stay unavailable until the actual distribution and jurisdiction review is complete. Private events do not need those stakes and remain free.
