# V3.3 executed test evidence

## Scope

This run implements new party modules against the existing game engine. It does not rewrite the Figma stylesheet, icons, normal app controller, economy authority or rating rules. Source hashes for unchanged production files are checked at commit time.

## Executed

`node --test tests/tournament.test.js tests/rooms.test.js tests/party-http.test.js`

76 tests passed, zero failures. Coverage includes circle schedules for every roster size 2-10, balanced starting turns, no repeated pairings, complete placement brackets, ten-player fixture counts (League 45, Knockout 15, Mixed 27), actual tied-group playoffs, three-draw recovery, sequential one-device fixtures, authoritative send-rule moves, increment/timeout behavior, ready deadlines, private pause/resume, all four exact payout tables and no missing fifth place.

SQLite/authority tests cover ten equal reservations, one-underfunded-player rollback, every table's complete payout conservation, duplicate commands/settlements, paid eligibility deny-by-default, strict boolean eligibility, shared account active-match locks, public restart refunds, private isolation, guest token persistence/hashing, hostile JSON, outsiders and operator-only cancellation. Existing Elo is asserted unchanged by tournament settlement. Held recipients stop automatic payouts for review.

Four real HTTP cases exercise authenticated LAN sessions, create/join/ready/moves, outsider/origin rejection, ten-player capacity with an eleventh rejected, and no player-supplied operator scope.

`python3 tests/party-browser.py`

Passed: fifth home-mode mount, public payout table, local mixed event, two separate browser clients joining the actual local HTTP party service, ready checks, alternating legal moves, exact-cell hover/dotted destination, straight route overlay, persisted-session reconnect, square board at widths 320/390/768, resignation and final placement rendering. No JavaScript page errors were recorded.

## Environment limitations

The browser environment blocked loopback navigation. The test used `page.set_content` and an explicit Python fetch bridge to the actual Node HTTP handler/SQLite service. The host shell and historical local theme CSS fixture were used to test the additive extension; fonts/CDN icons were not downloaded. This is functional/state evidence, NOT a new screenshot-equivalence, full-theme contrast, production-host, native-radio or ten-physical-phone audit.

The pre-existing economy suite was NOT rerun in this pass; its production domain/authority files are preserved rather than claimed newly certified. A helper update lets that suite inline the additive scripts and expect five home modes. CI should run the whole repository suite before deployment.

## Commands

- `npm run test:parties`: the 76 new Node tests.
- `npm run test:party-ui`: party browser checks; requires Python Playwright and Chromium.
- `npm test`: all repository Node tests, including earlier economy tests, in an integrated checkout.
- `npm run start:lan`: actual free same-Wi-Fi host.

Tests use generated fixture identities and synthetic account state under tests only. Production UI does not display invented tournament participants, winners or wallet balances.
