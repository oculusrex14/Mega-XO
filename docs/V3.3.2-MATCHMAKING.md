# V3.3.2 Matchmaking

## Research basis
This design borrows principles, not proprietary algorithms.

- Chess.com Live Chess starts with a narrow rating window and widens it over time, while retaining limits to avoid wildly uneven games: https://support.chess.com/en/articles/8639319-how-does-matchmaking-work-in-live-chess
- Clash Royale 1v1 uses similar Trophy counts; Global/Private Tournament matchmaking emphasizes current tournament progress and becomes more flexible when wait times increase: https://support.supercell.com/clash-royale/en/articles/1v1-battle-2.html and https://support.supercell.com/clash-royale/en/articles/global-tournaments-5.html
- FIDE Swiss pairing emphasizes objective/reproducible pairing, equal-score groups and avoiding repeat opponents: https://handbook.fide.com/chapter/GeneralHandlingRulesForSwissTournaments202602
- Glicko-2 and TrueSkill formalize uncertainty; TrueSkill explicitly treats similar inferred skill as the basis of good matches: https://www.glicko.net/glicko/glicko2.html and https://www.microsoft.com/en-us/research/project/trueskill-ranking-system/

Mega XO keeps the approved public K=24 Elo. Matchmaking is a separate server concern.

## Ranked
Search is mutual: both players' current windows must contain the rating gap.

- 0–10s: ±50
- 10–25s: ±100
- 25–45s: ±150
- 45s+: ±200
- 75s+ for Champion+: up to ±250

Placement players (<10 ranked games) use ±100, ±125, ±150, then ±200. Placement-vs-established is avoided for 30 seconds, then allowed only within 100 Elo.

Blocked accounts never match. Mutual friends never auto-match in Ranked. Recent queue opponents are avoided for 60 seconds; the existing 3-pairs/day rule still applies. Same-region is preferred for 35 seconds; cross-region then becomes eligible if both have waited. Server-measured latency over 350ms is rejected. Both players must afford the exact equal Coin entry. Opponent identity/rating stays hidden until both accept. Match-found acceptance expires after 15 seconds.

The oldest ticket is processed first and then chooses the closest compatible candidate using Elo gap, region, latency and rematch penalties. Users cannot set a custom Ranked rating range.

X/O is balanced over each player's recent queued games. The server picks the assignment that reduces combined recent first-move imbalance; ties remain random.

## Casual
Casual is free and never changes visible Elo. It uses a hidden matchmaking-only rating, anchored to Ranked Elo after placements or 1000 for a new player. Casual updates only that hidden value.

- 0–6s: ±100
- 6–15s: ±175
- 15–30s: ±250
- 30s+: ±350

Cross-region can begin after 12 seconds. Recent casual rematches are avoided for 18 seconds. A bot is never silently substituted.

## Public tournaments
Low, Medium, High and Premium remain separate pools. Stakes never buy easier opponents.

A 10-player lobby widens around its median rating:
- first 25s: ±100
- 25–60s: ±150
- 60s+: ±200
- hard final table spread: 200 Elo forever

Blocked players and server-recorded friends are not deliberately placed in the same paid public tournament. Private/free rooms are exempt.

At ten players, seeding is deterministic: rating descending, then ranked games, then stable account ID. The existing Groups + Knockout split creates balanced snake-style groups (1/4/5/8/9 versus 2/3/6/7/10). Once the event starts, fixtures are scheduled; there is no further queue matchmaking.

## Integrity
Queue state is server-side and ephemeral. No Coins/Crowns are reserved before both players accept. Client-selected queue opponents, queue-sniping through visible opponent data, friend farming, and unlimited wait-time widening are blocked by design.
