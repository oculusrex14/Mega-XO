# V3.3.3 implementation plan

Base: V3.3.2 at 493a81c8e6a3765a2615ed1339c5b236e2d91b05. Preserve the accepted theme packs, core game rules, rating mathematics, party formats and entry prices.

1. Identity: provider-subject identities, immutable searchable player tags, unique normalized usernames, avatars, recoverable sessions and deliberate provider linking. Never identify or merge accounts by email.
2. Guest: immediate offline play, device-only save, no false cloud guarantee. Link/create an account to back up and restore progress. Preserve existing local saves.
3. Persistence: authenticated, versioned cloud saves with compare-and-swap; preserve separate offline practice data and authoritative server wallet/rank. Explicit conflicts, no silent wallet merge.
4. Friends: search by tag or username; request/accept/decline/cancel/remove/block; profile stats; invite/accept/decline/cancel challenges; mutual friendship enforced by server.
5. Presence: expiring authenticated per-session heartbeats; foreground/away/offline; derive match/queue/lobby state from server records. Privacy settings and no fabricated online status.
6. UX: additive profile/sign-in pages, startup animation, themed queue/accept/wait/reconnect screens and lobby wait feedback. Reuse approved surfaces/fonts/icons and board geometry. Respect reduced motion. No video or CDN dependency for loading animations.
7. Integration: one same-origin runnable Node server mounts identity, social, existing economy and parties with the same principal/database; real Google/Apple configuration disabled until credentials exist. Native SDK integration contracts are explicit.
8. Verify: real SQLite/HTTP and signed-token tests, privacy/ownership/conflict/replay tests, friend challenge flow, queue lifecycle, two-client browser checks, themes/small viewport checks. Record exactly which suites execute and which external/native release checks remain.
