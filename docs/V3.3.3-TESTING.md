# V3.3.3 executed verification

## Baseline and preservation

Started at V3.3.2 `493a81c8e6a3765a2615ed1339c5b236e2d91b05`. A private GitHub Actions source archive supplied an exact checkout for local execution; no source files were reconstructed from snippets. Baseline Actions output had 138 tests, 126 passing and 12 failing. Eleven failures were the existing tournament account lookup against the exported array representation; one was exact floating-point symmetry in match-quality scoring.

The two inherited defects were corrected without changing thresholds: account lookup now accepts Map, exported account entries or Authority; match quality uses its algebraically equivalent symmetric form. This is not a change to Elo, queue windows, pots, payouts or tournament formats.

`src/styles.css`, `src/icons.js`, `src/game.js`, `src/domain.js`, `src/authority.js`, `src/tournament.js`, `src/party.css` and `src/party-ui.js` are byte-identical to the accepted base. Existing app/network integration points are extended explicitly; the game screen is reused for friends and queued matches.

## Node suite

Executed `npm test` with Node 22.16.0: **161 passed, 0 failed**. This is the complete pre-existing suite plus 23 new identity/community tests.

New coverage:

- anonymous sessions create no server wallet/profile;
- provider-subject registration, native claims, real RSA signature validation;
- Google code/PKCE callback, nonce/state/session binding and one-use/replay rejection;
- exact audience/issuer/expiry/issued-at/nonce checks, forged token rejection;
- unique case-normalized usernames, immutable player tags, restricted edits;
- explicit provider linking, conflicts without merges, session rotation, recent-auth checks, last-provider protection;
- cloud backup compare-and-swap, cross-device conflict, re-opening the database, persisted identity/tag;
- no offline-wallet promotion or Elo import;
- search, friend requests/acceptance/cancellation/removal/blocking and profile-stat privacy;
- heartbeat expiry, multidevice presence, hidden/away/in-match/queued derivation;
- actual HTTP friend invite/accept/play/resign and updated statistics;
- actual HTTP casual queue/accept/play/requeue and concealed opponent before acceptance;
- shared authenticated identity for online private rooms;
- CSRF, origin rejection and session revocation.

Signed provider tokens use test-only RSA keys with real signature checks. Those keys and the fixture token endpoint are not served by the production server. This is not evidence of live Google/Apple consent approval.

## Browser integration

Executed `python3 tests/community-ui.py`: the full current index/app/theme source with two independent browser-cookie sessions, using the actual combined HTTP/SQLite service.

Passed:

1. Four themed sign-in surfaces/loaders, guest flow and real bot response.
2. Native bridge contract through a signed-token fixture, profile/avatar/username editing.
3. Search -> friend request -> acceptance -> profile -> challenge -> accept -> legal moves in the existing game screen.
4. Friend profile statistics update after the completed server match.
5. Casual waiting animations, elapsed state and cancellation across all four themes.
6. Actual four-player local lobby/ready-count display with waiting feedback.
7. Manual cloud save, fixed board geometry after online moves, no horizontal page overflow at 320/390/768 widths, and zero JavaScript page errors.

Environment limitations: browser loopback navigation is blocked by administrator policy. The test therefore used `set_content`, separate cookie jars and a fetch bridge to the real Node handler rather than navigating directly to localhost. The current production styles are loaded, but Google Fonts/Lucide CDN requests are replaced by the already-shipped offline icon/font fallbacks. Screenshots were visually inspected for the new sign-in/queue surfaces. This is not a font-perfect theme audit, native-device test, live provider-consent test or distributed-load test.
