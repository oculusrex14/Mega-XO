# V3.3.4 — ranked direct challenges and notifications

Base: V3.3.3 `0b9e84db768dffed8c1396e272c0b173b3d8d414`.

This branch keeps the accepted Elo, rank tiers, challenge minimums, 10 Coins = 1 Crown conversion, 50/50 burn, weekly rewards and tournament economics unchanged. The pass focuses on making the ranked/direct-challenge lifecycle explicit and making pending social/game activity easy to find without cluttering the existing four themes.

## Ranked direct challenge lifecycle

1. A leaderboard challenge defaults to Ranked when both players have completed placements. Friend-profile challenges default to Unranked.
2. Ranked direct challenges use Crowns. Only the challenger funds the pot; the challenged player contributes 0.
3. The server remains authoritative for the challenger's and target's live rating/tier, the minimum Crown amount, friend cap, pair limits, placement eligibility, paid-entry eligibility and exact challenge terms.
4. Sending an invitation does not move funds. The challenger is recorded as having agreed to the exact terms; the target must explicitly accept.
5. The challenged player sees: challenger identity/rating, own entry (0), Crown pot, winner payout, retired amount, 30-second turn timer, expiry and the reminder that Crown size does not affect Elo.
6. Acceptance rechecks eligibility, balances, rating/tier and the immutable terms hash. A rating/tier change requires a fresh quote rather than silently changing the wager.
7. On acceptance, only the challenger contribution is reserved. Decline, cancellation and expiry cost nothing.
8. Ranked direct results use the existing Elo calculation and repeat-pair safeguards. Direct challenges receive no separate ranked win bonus.
9. Draws/operator voids refund the original contributor. Terminal settlement remains idempotent.

## Notification center

A bell is added beside Wallet/Settings. Its badge represents actionable incoming activity, not marketing unread counts.

The center shows:
- incoming direct challenges with Review;
- incoming friend requests;
- outgoing direct challenges with expiry and Cancel;
- an empty state when there is no pending activity.

Queue match-found still uses its existing time-sensitive acceptance sheet rather than being buried in the notification center.

## Notification preferences

Device alerts are opt-in and default to OFF. The in-app bell still shows pending activity even when device alerts are disabled.

Three groups are exposed:
- Matches & challenges
- Social
- Daily quests

Enabling the master device-alert switch requests permission only from a user gesture. A denied/unavailable permission leaves device alerts disabled and does not hide in-app activity. Browser notifications are emitted only while the app runtime is present and hidden; a native wrapper can implement the same contract through `MegaNativeNotifications`. Daily quest reminders are limited to locally verifiable quests to avoid false reminders about server-only progress.

## Theme and layout constraints

No changes are made to `src/styles.css`, `src/game.js`, `src/authority.js`, `src/tournament.js`, `src/party.css` or `src/party-ui.js`.

New surfaces use existing theme tokens:
- Vector Light keeps clean rounded utility surfaces.
- Midnight Club keeps dark raised panels and restrained glow.
- Paper Club uses irregular paper-card geometry and handwritten hierarchy.
- After Hours keeps squared arcade geometry and neon edge treatment.

The notification center is a bottom sheet rather than another navigation tab, keeping the five-item bottom navigation unchanged.
