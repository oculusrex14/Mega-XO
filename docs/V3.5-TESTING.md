## Email/password account coverage

The new account tests cover:
- email normalization to lowercase;
- syntactic email validation;
- duplicate normalized-email rejection;
- password minimum rules;
- salted scrypt password hashing rather than plaintext storage;
- one email Continue action selecting create versus sign-in on the server;
- a missing email remaining pending until a 6-digit OTP is verified, then creating the same authoritative profile/account model used by Google/Apple;
- an existing verified email/password restoring the same actor, stable player tag and edited username;
- a wrong password for an existing email failing without creating a duplicate account;
- OTP values stored as HMACs rather than plaintext;
- 10-minute expiry, 60-second resend cooldown, persisted failed-attempt counters and five-attempt lockout;
- legacy unverified email credentials being forced through OTP ownership verification;
- linking email/password to an existing Google/Apple profile only after OTP ownership verification;
- unlinking email while another recovery method remains;
- recent email reauthentication before sensitive identity changes;
- real HTTP unified email continuation and OTP verification using the existing HttpOnly session, origin and CSRF protections;
- generic forgot-password responses for known and unknown addresses;
- reset OTP verification, password replacement and older-session revocation;
- branded Resend transport payloads using Antimatter Innovations identity;
- cloud-practice-save recovery across a second browser/client session.

The targeted account command includes these tests:

`npm run test:accounts`

### What email tests do and do not establish

The source now enforces mailbox ownership through a one-time email code before activating a new first-party email identity, and the forgot-password flow uses the same verified-mailbox mechanism.

Automated tests use an isolated mail transport and therefore establish application logic, not real-world deliverability. They do **not** prove that `antimatterinnovations.com` DNS has been configured in the production Resend account, that a production API key is installed, or that Gmail/Outlook/etc. will place every message in the inbox. Those are deployment checks described in `V3.5.1-EMAIL-VERIFICATION.md`.

The Chromium flow uses the real HTML/JS/CSS, HTTP handlers and SQLite stores with isolated test providers at native billing/ad boundaries.

The V3.5.1 flow verifies:
- exactly one **Continue with email** entry button on the landing screen;
- that same button sending a verification OTP when the email is new;
- the OTP screen accepting the isolated mailbox code before account creation;
- self-profile opening only after verified account creation;

- Cosmetic Credit balance shown in Rewards & Themes;
- no board-frame gallery or frame purchase surface;
- the archived-board-collection notice;
- responsive Rewards & Themes layouts across the four retained themes at 320, 390 and 768 pixels;

- Crown-pack and Remove Ads purchase confirmation;
- restore preserving Remove Ads without duplicating consumable Crowns.

The browser harness inlines unchanged repository assets because direct loopback browser navigation is restricted in the validation environment, then bridges browser requests to the real local Node service with a per-browser cookie jar.

## Production gates still open

Automated correctness does not establish production readiness for identity or monetisation. Remaining work includes:
- Resend production account/API-key provisioning;
- SPF/DKIM domain verification for `antimatterinnovations.com` and an appropriate DMARC policy;
- production deliverability, bounce/complaint monitoring and email-abuse operations;
- real native Apple/Google billing adapters and receipt lifecycle;
- live ad SDK/provider configuration;
- trusted age/territory/privacy controls;
- physical-device lifecycle and accessibility checks;
- deployment/load/backups and production analytics;
- beta retention/monetisation evidence;
- live provider/store/device acceptance for the monetisation features that actually ship.

No live advertisements, real purchases or production emails are used by the automated test providers.
