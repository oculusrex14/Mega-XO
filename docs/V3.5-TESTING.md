Baseline: V3.4 `816c6f23dd67e25b3590610c0d515538a0ce6c38`. V3.5 source validation was repeated after the ad/purchase race fix in `8633dbb87c405abaf3289fac2715e11cfc5d4357`.

The 25 new Node tests cover policy/onboarding/cadence and exclusions, account-bound signed ad grants, ECDSA tampering, wrong users/units/items/timestamps, duplicate callbacks, caps across database connections/restarts, delayed completion attempts, boost start/expiry and exact sub-second boundaries, free Casual earning, cosmetic redemption, verified one-time purchases, restore/refund handling, origin/CSRF/authentication, 16 KiB body bounds, legacy purchase-route gating, and asynchronous ad/purchase lock ownership.

Browser checks exercise the actual HTML/JS/CSS, account authentication, HTTP handlers and SQLite stores. They verify: guest/disabled-provider states; gallery previews and all themes; explicit rewarded-ad choice through a signed SSV callback without wallet inflation; review/cancel/confirm for all three new products; owned states; visible frame equip; restore without duplicate Starter Crowns; and persistent Remove Ads entitlement.

## Browser environment qualification

Direct loopback browser navigation was blocked by the local environment. The test therefore inlines repository assets unchanged and bridges browser fetches through a per-browser cookie jar to the real localhost Node service. Identity, native billing and advertising SDK boundaries use isolated test providers under `tests/`; ad callbacks still undergo actual ECDSA verification. There are no test-provider routes in production.

This is functional, state and responsive-layout validation, not native SDK/device, live advertisement, real purchase, accessibility certification, external-font or pixel-equivalence validation. No live ad inventory was used.

## Reproducible CI

`.github/workflows/v35-validation.yml` runs the same Node, invariant, balance, population, monetisation-model and Chromium flow checks on pushes to V3.5. It installs Playwright 1.57.0 and Chromium, and retains the exact source archive, Node/invariant/browser logs, all three model reports and screenshots in `v35-validation` for seven days. The run's head SHA identifies precisely what was checked; a source checkpoint or an earlier green run is not a claim that later code passed.

Commands: `npm test`, `npm run test:invariants`, `npm run test:balance`, `npm run test:economy-sim`, `npm run test:monetization`, `npm run test:monetization-model`, `npm run test:monetization-ui`.

## Not established by these tests

No real-user revenue, purchase uplift, retention non-inferiority or optimal ad frequency is established. Native SDK/provider setup, actual billing and pending-transaction recovery, privacy/age/territory controls, store/ad approvals, signed refund notification integration, physical-device lifecycle, load/backups and production analytics remain release gates. Ads and new purchases default off. Existing paid-entry compliance is not enabled or approved by this work.
