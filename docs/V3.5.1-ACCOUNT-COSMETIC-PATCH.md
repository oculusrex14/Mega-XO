# V3.5.1 account and cosmetic-direction patch

Baseline: V3.5 `6a17bca67003a825de86c85a2875efcec7f11288`.

V3.5.1 is a focused account/profile and cosmetic-direction patch. It does not alter Elo, Ranked seasons, tournament economics, ad cadence, or the V3.4 competitive economy.

## Email and password accounts

Mega XO now supports one first-party **Continue with email** path in addition to Google and Apple.

### Current behavior

- The landing screen shows one **Continue with email** button, not separate sign-up and sign-in buttons.
- The player enters an email and password once. If that email already belongs to a Mega XO profile and the password matches, the existing profile is signed in.
- If the email has no Mega XO profile, the same Continue action creates one automatically with those credentials.
- Email addresses are normalized to lowercase for uniqueness and login and must be syntactically valid.
- New passwords must contain at least 10 characters, at least one letter, and at least one number.
- Passwords are never stored in plaintext. The server stores a random salt plus an scrypt-derived password hash.
- A successful Continue restores or creates the same authoritative account/profile/session model used by Google/Apple, including player tag, friends, cloud practice save, wallet, Elo, seasons and online records.
- A wrong password for an existing email is rejected and never creates a second account.
- An existing Google/Apple profile can add email/password as another recovery/login method.
- Email can be reauthenticated before sensitive linked-account changes.
- At least one login method must remain linked.

### Important release boundary

This branch validates email **format** and password ownership, but it does not yet prove ownership of the mailbox itself. Production email verification and password-reset/recovery delivery require an outbound transactional-email service and are still release gates.

Do not market the current source as "verified email" until that provider flow is added.

## Profile discoverability

The profile editor already existed for linked accounts, but V3.5.1 makes it explicit.

The Friends screen now exposes the signed-in player card as:

**View / edit your profile**

From there the player can edit:
- username;
- display name;
- avatar;
- stats visibility;
- online-presence visibility.

The stable MEGA player tag does not change when the username changes.

Guest players still have no cloud identity. Their Friends screen instead directs them to create a profile with email, Google or Apple.

## Cosmetic Credits

Cosmetic Credits remain **account-bound**:
- not purchasable;
- not convertible to Coins or Crowns;
- not transferable;
- not stakeable;
- not included in wealth or Elo.

The balance is now visible in two places for a linked player:
1. **Rewards & Themes**;
2. **Your Profile**.

The balance is explicitly described as saved for future themes.

## Board-frame collection archived

The V3.5 board-frame collection is no longer a current product direction.

V3.5.1 removes:
- the board-frame gallery from the rewards UI;
- Cosmetic Credit frame unlocks;
- frame redeem/equip player endpoints;
- the `style_collection` purchase;
- the `starter_100` Origin-frame bundle.

The current purchase catalogue is therefore:
- 100 Crowns;
- 525 Crowns;
- 1,100 Crowns;
- permanent Remove Ads.

Historic frame state may remain in old account data for migration compatibility, but V3.5.1 does not sell or expose that collection as a current feature.

Future visual monetisation should be designed around **full themes** rather than small board-frame cosmetics. Cosmetic Credits are reserved for that future theme system until a separate theme catalogue, pricing model and entitlement migration are specified.

## Validation targets

V3.5.1 adds/updates tests for:
- email normalization and uniqueness;
- password hashing and weak-password rejection;
- wrong-password behavior and automatic create-vs-sign-in selection;
- cross-session profile recovery;
- linking/unlinking email with Google/Apple identities;
- email reauthentication;
- real HTTP unified email continuation plus cloud-save recovery;
- Friends-page self-profile discoverability;
- username editing;
- Cosmetic Credit visibility;
- archived frame catalogue;
- Crown/Remove Ads-only purchase surface;
- existing V3.5 ad/economy invariants.
