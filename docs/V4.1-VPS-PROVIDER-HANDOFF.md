# Mega XO V4.1 VPS / provider handoff

Status: **repository work complete; external execution starts here**

This is the shortest path from a green V4.1 repository to a production-ready deployment. It does not replace the detailed runbooks; it tells the operator **what to do next and in what order**.

Canonical blocker ledger: `docs/V4-OPEN-BLOCKERS.md`.

## 0. Before touching the VPS

On a trusted machine:

```bash
git switch V4.1
git pull --ff-only
git status --short
git rev-parse HEAD
```

Requirements:

- working tree clean;
- exact V4.1 head has a green GitHub Actions validation run;
- do not paste secrets, OTPs, recovery keys, raw cookies, private keys or full message headers into GitHub/chat;
- record only non-secret evidence in `docs/V4-OPEN-BLOCKERS.md`.

Product rule to preserve:

- Ranked Coin entry, Crown challenges and public tournaments are normal closed-loop gameplay;
- bought and earned Crowns have identical gameplay utility;
- Coins/Crowns have no Mega XO cash-out or real-world redemption;
- native purchases and ads remain off until their own provider/device gates are complete.

## Phase 2 — network, DNS and deployment roots

Complete **EXT-02, EXT-03, EXT-04, EXT-10**.

### Oracle / host firewall

Public ingress:

- TCP 80;
- TCP 443.

Do not publish:

- Node 8080;
- metrics/admin ports;
- Docker API;
- SQLite;
- operator routes.

Prefer SSH/operator access through Tailscale.

### Hostinger DNS

Create:

```text
play.antimatterinnovations.com         A -> ORACLE_PUBLIC_IPV4
staging.play.antimatterinnovations.com A -> ORACLE_PUBLIC_IPV4
```

Do not create AAAA until IPv6 is proven end-to-end.

Verify:

```bash
getent ahostsv4 play.antimatterinnovations.com
getent ahostsv4 staging.play.antimatterinnovations.com
```

## Phase 3 — mail domain and Resend

Complete **EXT-05, EXT-12, EXT-35**.


```bash

  https://staging.play.antimatterinnovations.com \
```

Required evidence:

- signup OTP delivered/verified;
- forgot-password OTP delivered/verified;
- old password rejected after reset;
- same profile restored;
- SPF PASS;
- DKIM PASS;
- DMARC PASS;
- Google Workspace mail still works.

Reference: `deploy/EMAIL-LIVE-ACCEPTANCE.md` and `deploy/MAIL-DOMAIN-SECURITY.md`.

## Phase 4 — R2 encrypted backups

Complete **EXT-07, EXT-08, EXT-09, EXT-14**.

Create:

- private R2 standard-storage bucket;
- dedicated S3 token limited to the backup bucket/prefix.

Use separate prefixes:

```text
mega-xo-v4-staging
mega-xo-v4-production
```

Configure staging first:

```bash
sudo bash deploy/configure-r2-backup.sh \
  /opt/mega-xo-staging \
  CLOUDFLARE_ACCOUNT_ID \
  mega-xo-backups \
  --access-key-file /root/r2-access-key \
  --secret-key-file /root/r2-secret-key
```

Copy the generated Restic password to a secure location outside:

- the VPS;
- the Cloudflare account.

Do not commit the password.

After an immutable staging image is deployed:

```bash
sudo bash deploy/enable-backups.sh /opt/mega-xo-staging --initialize-new-repository
```

Required proof:

- first snapshot uploaded;
- `restic check` passes;
- snapshot retrieval succeeds;
- backup verifier passes;
- staging restore drill returns known account/wallet state.

Reference: `deploy/R2-BACKUP-RUNBOOK.md`.

```bash
  --tmpfs /tmp:size=1024m,mode=1777 \
  -e MEGA_CAPACITY_CLIENTS=24 \
```

Choose concurrency limits **below** the first degradation knee.

## Phase 14 — production tag and deploy

The backend release gate currently requires the infrastructure/operations rows defined in `scripts/release-gate.js`.

Before tagging:

```bash
git switch V4.1
git pull --ff-only
git status --short
git rev-parse HEAD
```

Then:

```bash
GITHUB_REF_NAME=v4.1.0 \
GITHUB_SHA=$(git rev-parse HEAD) \
node scripts/release-gate.js
```

Only if approved:

```bash
git tag -a v4.1.0 -m "Mega XO V4.1.0 production backend"
git push origin v4.1.0
```

After GitHub publishes the multi-arch image, use the immutable digest:

```bash
sudo bash deploy/verify-release.sh \
  ghcr.io/oculusrex14/mega-xo@sha256:IMAGE_DIGEST \
  TAGGED_GIT_SHA \
  4.1.0

sudo bash deploy/release.sh \
  /opt/mega-xo \
  ghcr.io/oculusrex14/mega-xo@sha256:IMAGE_DIGEST
```

Post-deploy:

```bash
sudo bash deploy/audit-perimeter.sh /opt/mega-xo
sudo bash deploy/check-health.sh /opt/mega-xo
```

From a separate machine:

```bash
node scripts/external-perimeter-probe.js \
```
