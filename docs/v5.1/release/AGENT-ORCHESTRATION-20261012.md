## Conflict prevention
`V5.1` is the sole shared development remote branch; `main` and `V4.1` are untouched. Main is the integration coordinator. Agents must read fresh HEAD before changes, use isolated local workspaces, coordinate overlapping files, make small meaningful commits, and use only fast-forward pushes. Never force-push; if branch advances, rebase/reconcile locally or hand off explicit commits/patches and let Main integrate. Do not create new remote branches unless explicitly agreed. Record every file-changing milestone and its exact SHA. Avoid simultaneous writes to `AGENTS.md`, common package manifests, original source ledgers, and deployment configs.

## Evidence and checkpoint protocol
For each R##, CL##, A## or P21 checkbox changed, record: original ID, previous/new state, primary owner, environment and date, exact git commit/image/build SHA, command/test/log/artifact link, observed result, known skips, remaining blocker and handoff next action. Preserve existing game rules, economy, crowns, themes, native/web parity and tutorial semantics. Count NOT_RUN separately from PASS. The Oct 12 broad suite had 727 tests: 722 pass, 2 fail, 3 skip; clear genuine failures and retain justified skips with citations.

### Mandatory escalation
Stop affected work, not all parallel work, when a required credential, paid action, irreversible external submission, shared schema/API ownership collision, app-store attestation, or live write/cutover is encountered. Ask only for the specific missing decision/input. Report real store states (draft/uploaded/testing/submitted/approved/live) distinctly. Do not claim bot strength or provider approval based on a green unit-test result.
