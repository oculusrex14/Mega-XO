Approach A: compact game-specific CNN policy, optional calibrated value head, tactical safeguards and PUCT/search, executed on the client. Approach B: offline Unsloth Qwen3.5-0.8B legal-option decision model as a measured teacher, with conditional distillation into the same small client student. The five-tier classical search ladder remains a measured independent baseline/fallback. No mandatory per-move serverLLM or always-on hostedGPU.

Classical improved Expert scored167W/54D/35L over256games/128paired families,75.78% points with approximately[71.29%,80.08%] paired bootstrap95% interval at scaled20ms on one host. This is not a full device acceptance claim. Current neural policy/value PUCT scored1W/1D/208L against improved Expert; policy-only2W/9D/199L. All candidates are unapproved. Diagnose weak targets/calibration/search behavior before spending larger training budgets.

The342,282-parameter model is approximately1.27MBgzip float/~0.327MBgzip INT8, but these exclude11.9MB WASM,optional23.8MB JSEP and JS/worker/installed-memory overhead. Desktop inference is not a phone thermal/battery result. An interval spanning parity is not an INT8 non-inferiority proof.

The existing champion_cycle.py only writes a manifest with empty steps; run_cmd is unused. Manual prior experiments are separate real evidence, not an executing learning service. generate.cjs has a neural-engine seam not selected by itsCLI; record actual root visits, not priors mislabeled asUCT. train.py remains a small in-memory bootstrap without production-scale streaming/resume.

## Operator and data design

Prefer independent single-device training first, not premature multi-nodeDDP. DGX1 trains/exports students; DGX2 generates/searches and independently evaluates, using scheduled GPU windows for teacher work. Measure CPUself-play versusGPU bottlenecks and disk/network throughput. Host separation does not by itself ensure unbiased evaluation.

Implement CREATED->GENERATING->DATA_VALIDATED->TRAINING->EXPORT_VALIDATED->EVALUATING->REJECTED or RESEARCH_APPROVED->DEVICE_VERIFIED->RELEASE_APPROVED->PUBLISHED. Add PAUSED and retryable/permanent failure states. These are proposed modes to implement, not currently working commands. Use argument arrays rather than untrusted shell strings, durable atomic manifests, exclusive leases/heartbeats, tracked children, bounded retries and checkpoint-safe stop. Verify the supplied sourceSHA against an actual clean tree; remove stale hardcoded defaults. Large data/checkpoints stay in ignored owner-controlled storage, sanitized manifests/tests stay inGit.

Record schema/rules/encoding versions,game/family IDs,replayable state/prefix,side to move,mask,root visits,played action,final outcome,valuePOV,models/search/budgets/seeds/provenance. Preserve planes8-v1 and b*9+c policy indexing. Value is final outcome for the recorded side to move; terminal state has no legal policy. Replay with G.apply, reject corrupt/incomplete records, and cap duplicates/family/source dominance.

Split entire games and D4-equivalent families before augmentation. Validation tunes parameters; confirmation holdout remains unseen by training and repeated candidate selection. Mining a still-active evaluation failure into training invalidates its holdout claim. A proposed replay start is50%recent/30%archive/20%hard-state sources, but measure and tune it; this is not an established optimum. Keep raw neural priors,search targets and played behavior separate. Save optimizer/scheduler/RNG/data cursor on interruption and distinguish warm-start from genuine resume.

Audit value sign with solved fixtures before patching it based on a bad league. Compare actual completed simulations/nodes and time spent in inference/critical-move filtering. Run both product wall-clock comparisons and controlled compute ablations;16neural simulations at30ms do not characterize all neural search. Policy-only with tactical evaluation is an acceptable winning design if value calibration remains harmful.

## Teacher experiment

Verify current FastDecisionModel/DecisionTrainer APIs and actual Qwen3.5-0.8B support in a separate environment. Use compact canonical state serialization and ALL legal optionIDs; test shuffled option ordering for shortcut bias. Do not parse generated prose into moves or silently count fallback moves as valid teacher answers. Strong search/solved labels are preferable to treating every weak self-play action as optimal. Preserve the family split instead of convenience random-row splits.

Calibrate on validation families, compare decisions/tactics/actual matches and cost per accepted target. OptionalRL is a separately supported experiment with verified canonical reward semantics, not self-grading prose. Generic language/decision benchmark gains are not MegaXOXO strength. A teacher can be useful offline despite excessive client latency, or be rejected as weak/expensive.

Distill only useful calibrated training-family policy; mix search supervision and teacherKL with validation-selected temperature/lambda. Distill value only when its calibration is independently established. Compare otherwise identical students with/without teacher data. Neither0.8Bweights nor a mandatory network API ships.
