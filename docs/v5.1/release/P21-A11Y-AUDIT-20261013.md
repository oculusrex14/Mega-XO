### What it checks, and how it avoids a false PASS

It parses the **built** HTML/CSS/JS bytes with no browser, so a hydrated DOM, a network fixture or a
synthetic render cannot satisfy it.

| Group | Checks |
| --- | --- |
| documents (45) | exactly one `<main>`; an `<h1>`; `lang`; viewport meta; non-empty `<title>`; no skipped heading level; unique `id`; no `tabindex > 0`; no focusable control inside `aria-hidden`; skip-link target resolves; skip-link coverage when ≥12 focusable controls precede `<main>`; runtime-rendered heading proven from the bundled script |
| media | `alt` on every `<img>` in built markup (182) and in the JS view templates (10); named-or-hidden inline `<svg>`; intrinsic `width`/`height` |
| controls | accessible name for every focusable control (1,896 in built markup) — `aria-labelledby`, `aria-label`, `label for`, wrapper `<label>`, `legend`, `value`, nested `alt`/`<title>`, then contents; JS-template buttons resolved from their template inputs |
| focus | every `outline:none|0` rule either carries a same-block visual differentiator, targets a programmatic focus target, or is covered by a focus rule |
| contrast | 14 token pairs × 4 board themes, plus same-block literal pairs and 20 CSS-derived cross-block component contexts |
| integrity | manifest hash/byte verification, resolution of every local asset reference (2,503), no unresolved local reference |

Honesty rules that keep the report from overstating a result:

- A check the harness cannot *prove* is `MANUAL_REVIEW`, never PASS.
- A palette-to-palette pair (one theme token against another theme token) is `OWNER_PALETTE`: it is
  measured and reported with its exact ratio, but it is not a failure, because an automated audit
  must not silently rewrite an owner-approved palette.
- A row is a component defect only when the colour comes from a component-specific declaration, a
  composited tint, a gradient, or a non-text token used as text colour.

**Coverage limits of the automated checks (stated, not hidden).** The harness does not model a
gradient's individual stops against a label (a whole gradient is one background), a border stroke
against the surface it divides, backdrop-blurred or image backdrops, or text over photographic art.
Defects 1 and 2 below were found by direct arithmetic for exactly those reasons; the same class of
finding can still exist elsewhere on the art-backed hero and is part of the manual review.

Two facts constrain any future change here, and both are why this unit left the values alone:

- The retained compatibility client already declares the identical `--muted` values in
  `src/styles.css` and the repository's own `tests/contrast.py` asserts a **4.0** bar for
  secondary text on the `vector` theme ("`secondary=4.0 if theme=='vector' else 4.5`"). Changing the
  practice-palette value while the game palette keeps it would create two conventions for one
  appearance, which is exactly what `P21-D004` forbids.
- These are owner-pinned appearance values, not free design choices. An automated accessibility
  audit is the right place to *measure and surface* them; deciding whether the approved appearance
  should shift is an owner visual decision, not a subagent edit.

**Recommendation for the owner:** accept the 22 recorded ratios as-is, or issue one explicit
appearance change for `--gb-muted` (vector), the four `--gb-line` values, `--gb-mini-border`, and
the two `--gb-route` values together with the matching `src/styles.css` palette, so the website and
the retained client stay byte-consistent.
