- **PR 18** `codex/provider-signin-availability` — provider sign-in availability, iOS signing chain.
- **PR 19** `codex/cashfree-web-payments` — Cashfree INR checkout for the web store.

## 1. P21 website validation regression (PR 18)

**Evidence it is a regression, not infrastructure.** `p21-web.yml` passes on base `1bbed36` and fails
on the PR. The failure is `{"id":"P21-REALTIME-RUNNER-ERROR","error_name":"TimeoutError","message":
"page.waitForFunction: Timeout 9000ms exceeded."}` — the first match never renders.

**Reproduced locally** (Playwright chromium, `scripts/p21/realtime-qa.cjs`):

| Tree | Result |
| --- | --- |
| `1bbed36` (base) | **PASS 21/21** |
| `02c9b62` (PR 18) | **FAIL** — `page.waitForFunction: Timeout 9000ms exceeded` |
| PR 18 + boot `loadProviders()` removed | FAIL |
| PR 18 + boot call removed + profile branch removed | FAIL |
| PR 18 + `loadProviders()` on the account render | **PASS 21/21** |

The boot-time `MegaAccount.session()` read is the cause, not the branch inside it. Loading providers
where the Google/Apple buttons actually render keeps PR 18's intent and passes both the account tests
(`tests/v5-p21-account-web.test.js` 7/7) and the browser harness.

## 2. Cashfree settlement (PR 19)

`server/cashfree.js` `verifyOrder()` returned `{status, amount}` after checking
`order_currency === 'INR'`, but `settleCashfree()` requires `verified.currency === 'INR'`. Every
genuine PAID order would have failed with `ORDER_AMOUNT_MISMATCH`. The PR's own tests passed only
because their fake provider injects a `currency` the real one never returns.

Proven with the real module over a fake transport (no network):

```text
before: verifyOrder -> {"status":"PAID","amount":89}          hasOwnProperty(currency) === false
after:  verifyOrder -> {"status":"PAID","amount":89,"currency":"INR"}
```

**Further finding, not fixed here (recorded, needs the owner's lane):** the new `cashfree:<orderId>`
receipt is written into `monetization.receipts`, whose PostgreSQL DDL is
`CHECK (store IN ('google','apple'))` (`packages/migrations/migrations/0015_monetization_store.sql:16`).
On the SQLite authority `server/production/**` (where PR 19 is wired) the table is unconstrained, so
the web checkout works there — but the **PostgreSQL** authority rejects a `cashfree` receipt. The
Codex handoff already schedules this as "Required work B" (a `commerce.cashfree_orders` migration plus
a `packages/services/commerce.js` port); it is not a merge blocker for the SQLite path but it must
land before the PG cutover, and it is why the store must not be advertised on the PG-backed site yet.

## 3. Migration coverage (PR 19)

The frozen migration source is V4.1.2 — 35 tables, no Cashfree (the provider post-dates it). PR 19
created `v52_cashfree_orders` unconditionally in the `MonetizationStore` constructor, so any snapshot
taken from a running store had 36 tables and the extractor failed closed:

```text
Error: COVERAGE_INCOMPLETE:table:v52_cashfree_orders (1 locator(s) unclassified; table:v52_cashfree_orders)
```

Failing before the fix: `tests/v5-migration-purity.test.js` (4 of 6 cases). Gating the DDL on the
Cashfree catalog removes the table from an unconfigured store and the file passes 6/6.

## 4. Native debug log (PR 18)

`android.util.Log.d("MegaNativeDebug", "finish_failed status=… body=" + raw.take(400))` printed the
first 400 bytes of a failed `/api/account/native/token` response — a body that carries
`accessToken`/`refreshToken`. Removed.
