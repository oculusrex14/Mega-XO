# E5 rehearsal on final V5.2 source (2026-10-14)

The strongest reversible rehearsal of the cutover, repeated on the **final V5.2** code rather than
the older `07c9fbab` build the original E5 used. Real production composition, real production
database, real production Redis, driven to a live HTTP surface — **without** an authority epoch, so
it was structurally incapable of becoming the serving authority. V4 was not touched.

## The fail-closed path was exercised first, not skipped

Before the migration was applied, the same command **refused to boot** with
`PRODUCTION_SERVER_FAILED SCHEMA_INCOMPATIBLE`: `packages/db/pg/readiness.js::verifyRuntimeSchema`
compares the live `meta.migrations` ledger row-for-row against the migration manifest, and V5.2's
manifest has 52 entries while production had 51. That is a real, reproduced demonstration that the
process cannot serve against a schema it does not match.

Other fail-closed refusals observed and fixed during the rehearsal (each a genuine missing
prerequisite, never worked around): `Cannot find module 'redis'` until `npm ci --omit=dev` installed
the declared dependency, and `INVENTORY_MISSING: production.json` until the tracked inventory was
present. The mail transport reported `{"event":"mail_deferred","reason":"transport_disabled"}`,
consistent with `outbound.email: "disabled"` in the production inventory — email stays off until its
own gate.

## Migration 0052 applied (additive, forward-only, target still non-serving)

`node scripts/v5/migrate.js --dry-run` → `52 migrations validated against manifest`, with 0052's
checksum matching (`sha256:6a0c5bc3…`). Then, with the exact confirmation guard:

```
V5_TARGET=production MIGRATE_CONFIRM=mega_xo_v5_production \
  node scripts/v5/migrate.js --execute --confirm-production
→ applied 0052_research_consent_and_retention
node scripts/v5/migrate.js --verify
→ verify OK: 52 checksums + catalog conformance
```

This is the same reversible-preparation class as the E2 import: it writes only to the **non-serving**
production database, creates the consent/retention tables, and does not make V5 the authority. No
first production *application* write has occurred, so the SQLite rollback option remains open.

## What this does and does not establish

Establishes: the final V5.2 image runs against real production data and Redis, serves the real web
bundle, fails closed on schema drift, refuses to arm early, and the production schema is at 52.
Does not establish: production cutover, V5 serving traffic, provider ad/store channels, or the E4
write fence. `P22 readiness` still returns `BLOCKED: OPERATOR_EVIDENCE_PACKET_MISSING`.
