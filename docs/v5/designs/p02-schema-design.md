1. GLOBAL CONVENTIONS

1.1 Schemas (owner-aligned so grants are schema-scoped where possible): meta, identity, profile, social, economy, core, match, tournament, monetization, cosmetics, season, privacy, audit, support, runtime, ops. [D]
1.2 Identifier/type rules [D, grounded in V validId/NAME/safeKey/validId regexes and V4 caps]:
- actor_id TEXT, PK-preserved verbatim; CHECK (actor_id ~ '^[A-Za-z0-9][A-Za-z0-9:_-]{0,159}$'). Never cast to uuid; never regenerate tags/provider subjects.
- operation keys/session ids/ticket ids/transaction ids: TEXT verbatim; key grammar CHECK (key ~ '^[A-Za-z0-9:_-]{1,160}$') where the legacy grammar applied; provider subjects TEXT CHECK length<=255.
- fingerprints: CHAR(64) CHECK (fingerprint ~ '^[0-9a-f]{64}$' AND length=64). DB never computes fingerprints [D].
- currency: BIGINT. Documented bound 0 <= v <= 9007199254740991 (2^53-1). All balance/escrow/amount columns carry CHECK. Ledger/journal amount is signed BIGINT with CHECK (abs(amount) <= 9007199254740991). Core validates Number.isSafeInteger or lossless-string/BigInt before write [V: domain.integer/add].
- Elo: NUMERIC(9,2), CHECK (v >= 0) for rating/peak/casual_rating, signed for deltas. Hundredths preserved exactly; no float recomputation at import [V: elo() rounds to *100].
- timestamps: timestamptz everywhere (from epoch ms via to_timestamp(ms/1000.0); ms precision). Calendar keys become DATE (daily day, weekly Monday-start week, snapshot day) or TEXT CHECK ('^[0-9]{4}-Q[1-4]$') for season ids.
- booleans: boolean NOT NULL DEFAULT false (SQLite 0/1 imported exactly).
- JSONB policy: allowed ONLY for bounded immutable/revisioned aggregates [V: ARCHITECTURE 'bounded immutable or revisioned board/room snapshots may be JSONB']: match.state_json, match.terms_json, match.quote_json, match.receipt_json, match.move_timings, match.extra, tournament.rooms.groups_json/final_refs_json/seed_json/quote_json/receipt_json/timing/extra, tournament.fixtures.state_json/history_json/mini, profile.profile_saves.payload, monetization/room receipt snapshots, privacy.deletion_receipts.retained, ops.outbox.payload (NULLed after drain), identity/actor legacy_extra. No global economy JSONB: state(id=1,json) is fully decomposed; no table holds the whole economy aggregate.
- Command responses/idempotency results are stored as TEXT (exact committed bytes, replay-verbatim) with CHECK ((response IS NULL) OR (response::jsonb IS NOT NULL)); results that are only new-write are TEXT too. Rationale: JSONB normalizes key order/whitespace, and the differential replay test (spec 01 §6) compares exact public responses [D]. Snapshot/board JSONB equality is compared after parse [D].

4. MIGRATION LEDGER (V5-02-03)
=====================================================================
[D, patterned on the verified v4_schema scheme but for PostgreSQL]:
 meta.migrations(id INTEGER PK, name TEXT NOT NULL UNIQUE, checksum CHAR(64) NOT NULL, applied_at timestamptz NOT NULL DEFAULT now(), runner TEXT NOT NULL, duration_ms INTEGER, schema_version INTEGER NOT NULL).
 checksum = sha256(name + '\n' + sql) - identical rule to server/production/migrations.js checksum() so the legacy ledger maps 1:1 at P03 and a mismatch raises MIGRATION_CHECKSUM_MISMATCH.
 Runner: connect to the DIRECT unpooled endpoint with TLS verification as migration_owner; SELECT pg_try_advisory_lock(<fixed key>) (if false -> another migrator is running, abort non-fatally); assert id contiguity (rows[i].id == migrations[i].id, else SCHEMA_NEWER_OR_INCONSISTENT); apply unapplied migrations strictly in id order, each in its own transaction (PostgreSQL DDL is transactional) inserting the history row in the same transaction; refuse to continue on any checksum mismatch; never truncate/drop.
 Runtime roles have no CREATE privilege and no schema ownership: DDL outside the runner fails by grant. Runtime constructors must not create tables (contrast with the verified V4 constructors that CREATE TABLE IF NOT EXISTS in their constructors - that behaviour is explicitly not carried forward).
 Expand/contract rules: (1) add columns nullable or with a constant default; (2) backfill in bounded batches with recorded checkpoints; (3) switch readers/writers in a release that is compatible with both shapes; (4) drop/rename only in a later contract migration after the switch release is no longer deployed; (5) never combine a destructive step with new-code deployment; (6) every migration must be safe to re-run after a partial failure (idempotent DDL: IF NOT EXISTS / guarded DO blocks); (7) migrations must not invoke time-sensitive constructors or mint rows.
 P02 must land the ledger, a clean-create path from zero, and upgrade tests for each supported schema; the SQLite v4_schema table's 8 rows (counts: v4_schema=8) become the P03 import provenance, not PG migration history.

5. IDENTITY / TYPE / RETENTION DECISIONS
=====================================================================
5.1 Text identities preserved exactly: actor ids (u_<uuid> and legacy variants), tags, usernames, display names, provider subjects, store google_id/apple_token, transaction ids, receipt keys. No uuid cast, no tag regeneration, no email-based identity merge. Email uniqueness equivalence preserved via PK/lower() unique index; P03 reports any existing collisions before activation.
5.2 Currency is BIGINT with the documented safe-integer bound; import converts JS numbers that are not safe integers into an actionable discrepancy, never a rounded value [V: domain.integer/add rejects unsafe values]. Elo stays NUMERIC(9,2) hundredths; import never recomputes Elo.
5.3 Operation keys + fingerprints per family (stored verbatim, never recomputed by SQL; a family-scoped table keeps each legacy uniqueness domain intact): economy (actor,key) from JSON.stringify([actor,key]); monetization (actor,key); party (actor,key) from JSON.stringify([actor,key]); social actor+':'+key; match moves (match_id,key). Canonical fingerprint inputs (documented, to be reproduced by the V5 Core path and by the P03 differential replay): economy sha256(JSON.stringify({principal,cmd})); party sha256(JSON.stringify(clone(cmd))); social sha256(JSON.stringify({command,target})); monetization sha256(JSON.stringify(command)); move sha256(JSON.stringify({actor,revision,move})). JSON.stringify is insertion-order dependent: importing rows must store legacy fingerprints verbatim and the V5 DTO/validator (packages/contracts) must preserve canonical key order; a differing recomputation is a defect, not a migration discrepancy.
5.4 NULL/drop decisions for legacy embedded fields: accounts[].friendCode/name are dropped as authoritative copies (identity.profiles is canonical; the embedded copies are re-derived by Core reads) - retained only for verification during import, not as a column; activeMatch is replaced by core.actor_occupancy; account.operations/ledger become tables; session_presence and party_guests are not migrated (explicit expiry, no asset/identity loss); _pendingReason is not migrated; _riskActors/riskFlags move to private columns excluded from views; v4_schema is superseded by meta.migrations; community_limits/v4_limits are retained as ops.rate_buckets until Redis owns them (P06) because mail spend budgets are durable records.
5.5 Permanence and tombstones: monetization.receipts, store_revocations, store_bindings, deletion_receipts (actor_hash/tombstone), season.weekly_payouts, economy.ledger and audit.operator_audit are permanent; runtime roles get no DELETE on them. Legacy pseudonymization wrote literal tombstone strings ('deleted_<hex>') into friends/history.opponent/season.opponents/matches.players/symbols/receipts/journal/rooms; therefore actor-referencing TEXT columns hold either an actor id or a tombstone string, and hard FK enforcement applies only to live aggregate tables (match.participants, core.actor_occupancy, tournament.room_players, monetization.*, identity.*). The importer classifies each reference (existing actor / known deletion-receipt tombstone / unknown -> discrepancy). Rationale: a hard FK would either reject real data or force a destructive rewrite that P03 forbids.
5.6 Unknown historical keys: every aggregate target that decomposes a serialized object carries a legacy_extra JSONB column (identity.actors via economy.actor_legacy_extra, match.matches.extra, tournament.rooms.extra, tournament.fixtures.extra, monetization.credits.extra) that receives every unmapped source key verbatim with the source locator recorded; nothing is silently dropped. P03 reconciliation reads these columns as the unknown-feature feedstock, and a later contract migration may drop a column only after the coverage manifest marks it resolved.
5.7 Import must not use constructors, addAccount, default grants, or time-rolling season normalization [V constructor hazards]; restore-path clamps (purchasedCoins<=coins etc.) are recorded as source transform rules with their condition and test case, not applied silently.

8. OPEN DESIGN RISKS AND BORING-DEFAULT RESOLUTIONS
=====================================================================
R1 JSONB float coercion for currency inside quote_json/terms_json. Resolution: all currency that constraints/reconciliation touch is duplicated into BIGINT columns (pool, contributions, escrow, receipts, payouts); quote_json is display/verbatim fidelity anchored by terms_hash; importer validates safe-integer round-trip. Exercised by A07 (per-actor reconciliation) and A09 (escrow/ledger).
R2 Command response fidelity (JSONB vs exact bytes). Resolution: store TEXT verbatim; no canonicalization. Exercised by A08 (deterministic re-import) and the differential replay gate.
R3 Fingerprint recomputation drift (JSON.stringify key order across runtimes). Resolution: store legacy fingerprints verbatim, pin canonical inputs in packages/contracts and document them; never recompute in SQL. Exercised by A08/A10 (duplicate/concurrent spend and replay).
R4 Tombstone/system references vs hard FKs. Resolution: soft-verified TEXT references plus deletion-receipt mapping; hard FKs only on live aggregate tables. Exercised by A07 (social/privacy state import).
R5 citext availability. Resolution: lower() unique functional index by default; enable citext only if §6.5 confirms. Exercised indirectly by A07/A12.
R6 Epoch->timestamptz conversion determinism/precision. Resolution: exact UTC ms conversion in the importer with recorded rule and fixture. Exercised by A08.
R7 Elo NUMERIC driver string return. Resolution: adapters parse NUMERIC as string and convert to hundredths BigInt/validated 2-decimal value; never binary float recomputation. Exercised by A09/A10.
R8 Pooled vs direct connections (advisory locks, session settings). Resolution: migrations/import/backup use the direct endpoint; runtime uses bounded pools; no session-lock assumptions. Exercised by A04/A05 and V5-02-04 transaction/rollback tests.
R9 board/state JSONB TOAST churn under rapid moves. Resolution: one row per match with revision CAS (already the source shape); revisit only if P19 measures contention. Exercised by A11/A17.
R10 Cross-schema deletion workflow atomicity (identity + economy + social + monetization + privacy). Resolution: Core command performs economic/occupancy/reference effects in one transaction (lock order §3.7); API owns intake, worker owns the policy-bound follow-up; no API-only wallet rewrite. Exercised by A07 (privacy/deletion state) and A11.
R11 Unknown historical keys. Resolution: legacy_extra JSONB per aggregate + P03 coverage manifest; contract drop only after resolution. Exercised by A06 (complete source coverage).
R12 Rate budgets losing durable semantics when moved to Redis. Resolution: mail spend budget rows stay durable in PostgreSQL ('mail-budget:*' rows kept out of the ephemeral namespace) even after Redis owns other buckets. Exercised by A21/A22 indirectly.
